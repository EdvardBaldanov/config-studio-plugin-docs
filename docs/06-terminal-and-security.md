# Исполнение команд на хосте и Модель безопасности 🛡️

Config Studio позволяет плагинам взаимодействовать с операционной системой хоста: запускать компиляторы, утилиты git, линтеры или веб-серверы. При этом система оснащена многоуровневой защитой от опасных действий.

---

## 🔒 Модель Безопасности

```
+-------------------------------------------------------------+
| Запрос плагина: window.ConfigStudio.exec(...)               |
+-------------------------------------------------------------+
                              │
                              ▼
        +---------------------------------------------+
        | 1. Проверка жесткого Черного Списка (Go)    |
        +---------------------------------------------+
              │                                 │
     (Совпадение найдено)               (Команда не в ЧС)
              │                                 │
              ▼                                 ▼
   ❌ ОШИБКА 403 БЛОКИРОВКА        +---------------------------+
  "Strictly prohibited command"    | 2. Проверка уровня риска  |
                                   +---------------------------+
                                          │             │
                                     (Рискованная)   (Безопасная)
                                          │             │
                                          ▼             ▼
                     +---------------------------+   ✅ ВЫПОЛНЕНИЕ
                     | Режим "Я знаю что делаю"? |
                     +---------------------------+
                            │             │
                         (НЕТ)          (ДА)
                            │             │
                            ▼             ▼
              +-----------------------+  ✅ ВЫПОЛНЕНИЕ
              | Диалог подтверждения  |
              | у пользователя (UI)   |
              +-----------------------+
```

---

## 🚫 1. Жесткий Черный Список (Нельзя обойти)

Следующие команды и шаблоны **категорически блокируются ядром** Config Studio и никогда не выполняются:

1. Рекурсивное удаление корневых или системных директорий:
   - `rm -rf /`, `rm -rf /*`, `del /f /s /q c:\*`
2. Форматирование файловых систем и дисков:
   - `mkfs`, `format C:`, `format D:`
3. Прямая перезапись сырых блочных устройств:
   - `dd if=... of=/dev/...`
4. Редактирование разметки таблиц разделов:
   - `fdisk`, `parted`, `gdisk`
5. Выключение и перезагрузка операционной системы:
   - `shutdown`, `reboot`, `poweroff`, `halt`, `init 0`, `init 6`
6. Форк-бомбы:
   - `:(){ :|:& };:`

## ⚠️ 2. Рискованные команды и подтверждение

Команды, которые могут повлиять на системные пакеты или конфигурацию, по умолчанию вызывают всплывающее модальное окно с вопросом к пользователю:

- Установка и удаление системных пакетов: `apt install`, `yum remove`, `pacman -S`, `apk add`.
- Скачивание скриптов в оболочку: `curl ... | bash`, `wget ... | sh`.
- Массовая смена прав: `chmod -R 777`, `chown -R`.
- Остановка системных демонов: `systemctl stop`, `service ... stop`.
- Очистка контейнеров: `docker system prune`.

### Режим «Я знаю, что делаю» (Unrestricted Mode)
В окне **«Настройки» → «Плагины»** администратор может включить режим повышенных привилегий. При этом:
- Интерактивные подтверждения отключаются.
- **Жесткий черный список (пункт 1) остается активным всегда**, предотвращая случайное уничтожение системы.

## 💻 Исполнение разовых команд (`exec`)

```javascript
try {
  const res = await window.ConfigStudio.exec({
    pluginId: 'my-plugin',
    command: 'git',
    args: ['diff', '--stat'],
    cwd: './data/configs' // Рабочая директория (опционально)
  });

  if (res.exitCode === 0) {
    console.log('Вывод команды:\n', res.stdout);
    console.log(`Затрачено: ${res.durationMs}ms`);
  } else {
    console.error('Ошибка исполнения:\n', res.stderr);
  }
} catch (err) {
  // Вызывается, если пользователь отклонил подтверждение или команда запрещена
  console.error('Запрос отклонен:', err.message);
}
```

## ⚙️ Запуск долгоживущих процессов (`startProcess`)

Для серверов предпросмотра, наблюдателей за файлами (watchers) или фоновых компиляторов:

```javascript
// Запуск локального сервера разработки
const processInfo = await window.ConfigStudio.startProcess({
  pluginId: 'my-plugin',
  command: 'php',
  args: ['-S', '0.0.0.0:8085'],
  port: 8085
});

console.log('ID процесса:', processInfo.id);
console.log('Системный PID:', processInfo.pid);
console.log('Статус:', processInfo.status); // 'running'

// Остановка процесса при закрытии панели или отключении плагина
await window.ConfigStudio.stopProcess(processInfo.id);
```

> 💡 **Автоматическая очистка**: При отключении или удалении плагина пользователем Config Studio **автоматически завершает все запущенные им фоновые процессы**, гарантируя отсутствие утечек ресурсов или занятых портов.
