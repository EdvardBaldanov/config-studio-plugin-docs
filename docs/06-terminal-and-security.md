# Исполнение команд на хосте и Модель безопасности 🛡️

Config Studio спроектирован по принципу: **«Любое действие, затрагивающее production, должно быть явным, обратимым, журналируемым и подтверждаемым»**.

---

## 🔒 Архитектура безопасности: Многоуровневый фильтр

```
[ Установка плагина: ZIP / URL / Каталог ]
                    │
                    ▼
     [ 1. Изоляция в tmpDir & Аудит ]
                    │
                    ▼
     [ 2. Zero-Trust Анализ Разрешений ]
     - Белый список спецификации
     - Неизвестные права ➔ Critical Risk ⚠️
                    │
                    ▼
     [ 3. Экран Согласия (Consent Dialog) ]
     - Пользователь явно подтверждает права
                    │
                    ▼
[ Исполнение команды: window.ConfigStudio.exec(...) ]
                    │
                    ▼
     [ 4. Runtime Проверка Прав Плагина ]
     - Проверка наличия 'shell.exec' в манифесте
                    │
                    ▼
     [ 5. Жесткий Черный Список (Go Ядро) ]
     - Нельзя обойти ни при каких условиях
                    │
                    ▼
     [ 6. Pre-Save Guard & Audit Log ]
     - Валидация AST синтаксиса и запись в аудит
```

---

## 🛡️ 1. Zero-Trust Модель Разрешений (Fail-Secure)

При установке плагина ядро проверяет каждую запись в массиве `permissions`:

- **Белый список стандартных привилегий:**
  - `fs.read` (Low) — чтение файлов проекта.
  - `fs.write` (Medium) — запись и создание файлов.
  - `shell.exec` / `terminal.exec` (Critical) — запуск команд в ОС.
  - `remote.exec` (Critical) — команды по SSH.
  - `network`, `network.bind` (Medium) — локальные порты и сокеты.
  - `secrets`, `secrets.access` (Critical) — доступ к паролям и ключам из Keychain.
  - `service:<name>` (Medium) — вызов межплагинного RPC-сервиса.
  - `*` (Critical) — полный неограниченный доступ.

> 🔴 **Принцип Fail-Secure:** Любые неизвестные или нестандартные разрешения вне официальной спецификации **никогда не помечаются как безопасные**. Они автоматически классифицируются как **`Critical Risk` (`Неизвестно / Высокий риск`)**, а пользователю в окне согласия выводится предупреждающий красный баннер.

## 🚫 2. Жесткий Черный Список (Нельзя обойти)

Следующие команды **категорически блокируются ядром Go** и отклоняются со статусом HTTP 403:

1. Рекурсивное удаление системных директорий:
   - `rm -rf /`, `rm -rf /*`, `del /f /s /q c:\*`
2. Форматирование дисков и файловых систем:
   - `mkfs`, `format C:`, `format D:`
3. Прямая перезапись сырых блочных устройств:
   - `dd if=... of=/dev/...`
4. Редактирование разметки таблиц разделов:
   - `fdisk`, `parted`, `gdisk`
5. Выключение и перезагрузка операционной системы:
   - `shutdown`, `reboot`, `poweroff`, `halt`, `init 0`, `init 6`
6. Форк-бомбы:
   - `:(){ :|:& };:`

## ⚠️ 3. Рискованные команды и подтверждение (Human-in-the-Loop)

Команды, способные повлиять на системные пакеты или конфигурацию хоста, вызывают диалог подтверждения:
- `apt install`, `yum remove`, `pacman -S`, `apk add`
- `curl ... | bash`, `wget ... | sh`
- `chmod -R 777`, `chown -R`
- `systemctl stop`, `service ... stop`
- `docker system prune`

### Режим «Я знаю, что делаю» (Privileged Mode)
Включается администратором на ограниченный срок (сессия 15 минут) для непрерывной автоматизации. **Жесткий черный список (пункт 2) остается активным всегда.**

## 📋 4. Встроенный Журнал Аудита (Core Audit Log)

Ядро ведет непрерывный журнал всех критических событий в файле `audit.jsonl` и кольцевом буфере в оперативной памяти:
- `file.save`, `file.forcesave` (сохранение с обходом ошибок синтаксиса), `file.delete`, `file.create`, `file.rename`.
- `plugin.install`, `plugin.toggle`, `plugin.delete`.
- `shell.exec` (кто запустил, аргументы, exit code, время выполнения).
- Фиксация SHA-256 хеша содержимого до и после изменения.

Журнал доступен для просмотра и фильтрации прямо в окне **«Настройки» → «Аудит»** и нижней панели **«Вывод / Аудит»**.

---

## 🔑 5. Защита Секретов и Учетных Данных

- Пароли, приватные SSH-ключи и API-токены хранятся в защищенном системном хранилище (Windows Credential Manager / macOS Keychain / Secret Service) или зашифрованном Vault (AES-256-GCM).
- Плагин может запросить секрет только при наличии разрешения `secrets` в манифесте.
- **100% Zero-Secret Гарантия:** При экспорте профиля рабочего места (`config-studio-profile.json`) секреты принудительно исключаются из выгрузки.
