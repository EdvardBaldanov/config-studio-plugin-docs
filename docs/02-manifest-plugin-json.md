# Спецификация Манифеста `plugin.json` 📄

Файл `plugin.json` — это декларативный паспорт плагина, содержащий метаданные, точку входа, запрашиваемые системные привилегии, зависимости и настройки интеграции в интерфейс.

---

## 📋 Пример полного манифеста

```json
{
  "id": "quick-deploy",
  "name": "Quick Deploy & Remote Sync",
  "version": "1.9.0",
  "description": "Синхронизация и деплой конфигураций на удаленные серверы через SSH",
  "author": "Edvard Baldanov",
  "icon": "server",
  "entry": "main.js",
  "css": "style.css",
  "permissions": [
    "ui.panels",
    "toolbar",
    "contextmenu",
    "service:ssh",
    "secrets.access"
  ],
  "dependencies": {
    "ssh-client": ">=1.0.0"
  },
  "optionalDependencies": {
    "yaml-formatter": ">=1.0.0",
    "theme-high-contrast": ">=1.0.0"
  },
  "providesServices": [
    "deployer"
  ],
  "fileMatches": [
    "docker-compose*.yml",
    "nginx.conf",
    "*.env"
  ],
  "locales": {
    "ru": {
      "name": "Быстрый деплой и синхронизация",
      "description": "Синхронизация и деплой конфигураций на удаленные серверы через SSH"
    },
    "en": {
      "name": "Quick Deploy & Remote Sync",
      "description": "Sync and deploy configs to remote servers over SSH"
    }
  },
  "actionToolbar": {
    "primaryAction": "deploy",
    "targets": [
      { "id": "deploy", "label": "Deploy to Fleet" },
      { "id": "dry-run", "label": "Dry Run (Diff Only)" }
    ],
    "hotkey": "F5"
  },
  "minAppVersion": "1.9.0"
}
```

## 🔍 Справочник всех полей манифеста

| Поле | Тип | Обязательное | Описание | Пример |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `string` | **Да** | Уникальный ID плагина (`a-z`, `0-9`, `-`, `_`). Должен совпадать с именем директории. | `"quick-deploy"` |
| `name` | `string` | **Да** | Название плагина по умолчанию (если не переопределено в `locales`). | `"Quick Deploy"` |
| `version` | `string` | **Да** | Версия по стандарту SemVer (`MAJOR.MINOR.PATCH`). | `"1.9.0"` |
| `description`| `string` | **Да** | Описание возможностей плагина для каталога и настроек. | `"Deploy configs over SSH"` |
| `author` | `string` | Нет | Имя автора или организации. | `"Edvard Baldanov"` |
| `icon` | `string` | Нет | Иконка плагина из библиотеки [Lucide Icons](https://lucide.dev/icons) (`server`, `terminal`, `globe` и др.). | `"server"` |
| `entry` | `string` | **Да** | Относительный путь к главному JavaScript-файлу плагина. | `"main.js"` |
| `css` | `string` | Нет | Относительный путь к файлу стилей CSS (инжектится при старте). | `"style.css"` |
| `permissions`| `string[]`| Нет | Список запрашиваемых разрешений ядра и хоста. | `["ui.panels", "service:ssh"]` |
| `dependencies`| `object` | Нет | Словарь обязательных (жестких) плагинов с версиями SemVer. Без них плагин не сможет запуститься. | `{"ssh-client": ">=1.0.0"}` |
| `optionalDependencies`| `object` | Нет | *(v2.0.0+)* Словарь рекомендуемых (мягких) плагинов-расширений. Предлагаются к установке в 1 клик, но не блокируют запуск плагина. | `{"yaml-formatter": ">=1.0.0"}` |
| `providesServices`| `string[]`| Нет | Список межплагинных сервисов, регистрируемых плагином в шине RPC. | `["ssh", "deployer"]` |
| `fileMatches`| `string[]`| Нет | Маски файлов, при открытии которых активируется тулбар и действия. | `["Makefile", "docker-compose*.yml"]` |
| `locales` | `object` | Нет | Встроенные словари локализации названия и описания (`ru`, `en`). | `{"ru": {...}, "en": {...}}` |
| `localization`| `object` | Нет | Декларация плагина как **UI Language Pack** для всего интерфейса редактора. | `{"code": "de", "name": "Deutsch", ...}` |
| `actionToolbar`| `object`| Нет | Конфигурация сплит-кнопки панели действий `[ ▶ Action | ▾ ]`. | См. раздел тулбара |
| `minAppVersion`| `string`| Нет | Минимальная версия ядра Config Studio для работы плагина. | `"1.9.0"` |

## 🛡️ Модель Разрешений и Безопасность (Zero Trust / Fail-Secure)

Config Studio использует строгую модель безопасности **Zero Trust**: при установке плагина пользователь видит диалог согласия (**Plugin Consent Dialog**), где каждая привилегия проверяется и классифицируется по уровню риска.

### Официальный белый список разрешений:

| Разрешение | Уровень риска | Назначение |
| :--- | :--- | :--- |
| `ui.*`, `ui.panels` | 🟢 **Safe** | Добавление сплит-панелей, нижних панелей и элементов шапки. |
| `contextmenu` | 🟢 **Safe** | Добавление кастомных пунктов в контекстное меню проводника файлов. |
| `toolbar` | 🟢 **Safe** | Интеграция сплит-кнопок быстрых действий в верхнюю панель инструментов. |
| `fs.read` | 🔵 **Low risk** | Чтение файлов проекта и конфигураций в рабочей директории. |
| `fs.write` | 🟡 **Medium risk** | Запись, изменение и создание конфигурационных файлов на диске. |
| `network`, `network.bind` | 🟡 **Medium risk** | Запуск локальных веб-серверов и отправка сетевых HTTP-запросов. |
| `service:<name>` | 🟡 **Medium risk** | Вызов API межплагинного сервиса `<name>` через безопасную Proxy-шину. |
| `shell.exec`, `terminal.exec`| 🔴 **Critical (High)** | Выполнение системных консольных команд на хосте через ядро. |
| `remote.exec` | 🔴 **Critical (High)** | Удаленное выполнение команд по SSH на серверах парка. |
| `secrets`, `secrets.access` | 🔴 **Critical** | Доступ к защищенным паролям, токенам и SSH-ключам из OS Keychain / Vault. |
| `*` | 🔴 **Critical (Full)** | Полный неограниченный доступ ко всем системам редактора и хоста. |

> ⚠️ **Принцип Fail-Secure:** Любые неизвестные или кастомные разрешения, не входящие в спецификацию Config Studio, автоматически помечаются как **Критический риск (`Unknown / High Risk`)**. Ядро блокирует их скрытое выполнение и выводит предупреждающий красный баннер в окне установки.

## 🔗 Межплагинные Зависимости (`dependencies` и `optionalDependencies`)

Config Studio поддерживает трехуровневую модульную архитектуру:
1. **Автономные плагины:** Работают независимо и не требуют сторонних модулей.
2. **Обязательные зависимости (`dependencies`):** Жестко необходимые плагины-провайдеры сервисов (например, SSH-транспорт или парсер AST).
3. **Необязательные зависимости (`optionalDependencies`, v2.0.0+):** Рекомендуемые модули расширения (линтеры, темы, дополнительные форматировщики), обогащающие функционал плагина при наличии.

```json
{
  "dependencies": {
    "ssh-client": "^1.2.0"
  },
  "optionalDependencies": {
    "yaml-formatter": ">=1.0.0",
    "theme-high-contrast": ">=1.0.0"
  }
}
```

### 📊 Сравнение: Hard vs Soft зависимости

| Параметр | Обязательные (`dependencies`) | Необязательные (`optionalDependencies`) |
| :--- | :--- | :--- |
| **Поведение при отсутствии** | Блокирует запуск плагина (статус ошибки зависимости) | Плагин запускается и работает штатно в базовом режиме |
| **Экран согласия (Consent Dialog)** | Выделяется янтарным предупреждением с требованием установки | Выделяется фиолетовой карточкой с **чекбоксами выборочной установки** |
| **Порядок загрузки (DAG)** | Провайдер всегда загружается раньше потребителя | Если опциональный плагин включен, он также загружается раньше потребителя |
| **Защита от удаления (Cascade)** | Защищен: нельзя удалить или отключить провайдер (`409 Conflict`) | **Разрешено**: отключение или удаление мягкой зависимости не блокируется |
| **Вызов в коде** | `services.get(name, consumerId)` (выбрасывает ошибку при отсутствии) | `await services.getOptional(name, consumerId)` (возвращает `null`, если сервис недоступен) |

### 🛠️ Возможности движка зависимостей:
1. **Выборочная установка в 1 клик:** При установке плагина пользователь видит список рекомендуемых дополнений с галочками и может установить всё сразу одной кнопкой «Разрешить и установить».
2. **Топологический порядок загрузки (DAG):** Сервисы-провайдеры гарантированно инициализируются раньше зависимых модулей.
3. **Безопасная изоляция:** Опциональные зависимости не создают мертвых блокировок (Deadlocks) — если пользователь удалит рекомендованный форматировщик, основной плагин продолжит работу без сбоев.

## ⚡ Предоставление сервисов (`providesServices`)

Если ваш плагин предоставляет API-сервис для других плагинов (например, SSH-соединение или линтер):

```json
"providesServices": ["ssh", "sftp"]
```

В коде плагина вы регистрируете реализацию:
```javascript
window.ConfigStudio.services.register('ssh', {
  exec: async (host, cmd) => { /* ... */ },
  upload: async (host, local, remote) => { /* ... */ }
}, 'my-ssh-plugin');
```

## 🌍 Локализация (`locales` и `localization`)

### 1. Автономная локализация плагина:
Чтобы название и описание плагина автоматически переводились на язык пользователя:

```json
"locales": {
  "ru": {
    "name": "Форматировщик YAML",
    "description": "Автоматическое выравнивание отступов и валидация структуры"
  },
  "en": {
    "name": "YAML Formatter",
    "description": "Automatic indentation alignment and structure validation"
  }
}
```
*Также поддерживается вынесение словарей в отдельные файлы `locales/ru.json` и `locales/en.json`.*

### 2. Языковые пакеты интерфейса (UI Language Packs):
Если плагин добавляет в Config Studio поддержку нового языка для всего редактора:

```json
"localization": {
  "code": "de",
  "name": "Deutsch",
  "flag": "🇩🇪",
  "translations": {
    "settings": "Einstellungen",
    "save": "Speichern"
  }
}
```
После установки в настройках редактора появится новый пункт выбора языка с флагом `🇩🇪` и бейджем `Pack`.

## 🎯 Панель действий 1-Click Action Toolbar (`actionToolbar`)

Для плагинов, автоматизирующих запуск задач (Makefile, Docker Compose, сборщики):

```json
"actionToolbar": {
  "primaryAction": "build",
  "targets": [
    { "id": "build", "label": "build (Default)" },
    { "id": "test", "label": "test" },
    { "id": "deploy", "label": "deploy" }
  ],
  "hotkey": "F5"
}
```
- Создает в верхней панели сплит-кнопку `[ ▶ Run: build | ▾ ]`.
- Клик по левой половине мгновенно запускает действие в 1 клик (или по горячей клавише `F5`).
- Стрелка `▾` открывает выбор других целей.
- Благодаря `fileMatches` кнопка отображается **только** для соответствующих файлов, сохраняя нулевой визуальный шум (Zero-Clutter) на обычных конфигах.
