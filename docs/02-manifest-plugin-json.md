# Спецификация Манифеста `plugin.json` 📄

Файл `plugin.json` — это декларативный паспорт плагина, содержащий метаданные, точку входа, запрашиваемые системные привилегии и маски файлов.

---

## 📋 Пример полного манифеста

```json
{
  "id": "advanced-devkit",
  "name": "Advanced DevKit Pro",
  "version": "1.2.0",
  "description": "Инструменты для компиляции, автодополнения и отладки веб-сервисов",
  "author": "Edvard Baldanov",
  "icon": "terminal",
  "entry": "main.js",
  "css": "style.css",
  "permissions": [
    "ui.panels",
    "terminal.exec",
    "network.bind"
  ],
  "fileMatches": [
    ".html",
    ".php",
    ".json",
    ".yaml"
  ],
  "minAppVersion": "1.1.0"
}
```

---

## 🔍 Описание всех полей

| Поле | Тип | Обязательное | Описание | Пример |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `string` | **Да** | Уникальный ID плагина. Допускаются только символы `a-z`, `0-9`, дефисы `-` и подчеркивания `_`. Должен совпадать с именем директории плагина при установке. | `"web-devkit"` |
| `name` | `string` | **Да** | Читаемое название плагина, отображаемое в списках, каталоге и тулбаре. | `"Web DevKit"` |
| `version` | `string` | **Да** | Версия плагина в формате SemVer (`MAJOR.MINOR.PATCH`). | `"1.1.0"` |
| `description`| `string` | **Да** | Краткое описание возможностей плагина. Отображается в окне настроек. | `"Live HTML & PHP preview"` |
| `author` | `string` | Нет | Имя автора или команды разработчиков. | `"Config Studio Team"` |
| `icon` | `string` | Нет | Иконка плагина. Поддерживаются имена иконок библиотеки [Lucide Icons](https://lucide.dev/icons) (`globe`, `server`, `terminal`, `code`, `cpu` и т.д.). | `"globe"` |
| `entry` | `string` | **Да** | Путь к главному исполняемому JavaScript-файлу относительно корня плагина. | `"main.js"` |
| `css` | `string` | Нет | Путь к файлу стилей CSS. Если указан, стили автоматически инжектятся в `<head>` документа при активации плагина и удаляются при отключении. | `"style.css"` |
| `permissions`| `string[]`| Нет | Список запрашиваемых разрешений для доступа к API редактора и хост-системы. | `["ui.panels", "terminal.exec"]` |
| `fileMatches`| `string[]`| Нет | Список расширений файлов, при открытии которых активируются специфичные обработчики плагина. | `[".html", ".php"]` |
| `minAppVersion`| `string`| Нет | Минимальная версия Config Studio, требуемая для работы данного плагина. | `"1.1.0"` |

## 🛡️ Модель Разрешений (`permissions`)

Config Studio использует явное декларирование привилегий:

### 1. `ui.panels`
- **Что дает**:
  - Регистрация кнопок в панели инструментов редактора (`registerToolbarButton`).
  - Создание сплит-панелей Split-Screen справа от редактора (`registerSplitPanel`, `toggleSplitPanel`).
  - Создание нижних панелей (`registerBottomPanel`, `toggleBottomPanel`).
  - Добавление кастомных интерактивных виджетов в шапку (`registerHeaderItem`).
- **Когда требуется**: Практически любому плагину, изменяющему графический интерфейс.

### 2. `terminal.exec`
- **Что дает**:
  - Исполнение разовых консольных команд на хост-машине через `window.ConfigStudio.exec(...)`.
  - Запуск долгоживущих фоновых процессов (компиляторы, сборщики, линтеры) через `window.ConfigStudio.startProcess(...)`.
- **Безопасность**:
  - Все команды валидируются бэкендом Go на основе жесткого черного списка опасных команд.
  - Потенциально деструктивные команды вызывают интерактивное модальное окно подтверждения пользователя.

### 3. `network.bind`
- **Что дает**:
  - Открытие локальных сетевых сокетов и портов (например, запуск веб-серверов на портах `:8085`, `:3000`).
  - Подключение к внешним или удаленным сетевым эндпоинтам через `window.ConfigStudio.setRemoteEndpoint(...)`.

---

## ⚠️ Правила валидации манифеста

1. Манифест обязан быть валидным JSON-файлом в кодировке UTF-8.
2. Поле `id` не должно содержать пробелов, спецсимволов или путей перехода (`..`, `/`, `\`).
3. Файл, указанный в `entry`, обязан физически присутствовать в архиве или папке плагина.
4. При распаковке архива Config Studio автоматически находит `plugin.json` даже если внутри архива файлы упакованы в подпапку (например, при скачивании архивов GitHub `repo-name-main/`).
